## 1. Triage: do you even need RL? (first 5 min)

```text
Dynamics known/deterministic?
├── scheduling / routing / allocation / knapsack / matching
│     -> scipy.optimize.milp (HiGHS) or CP-SAT; exact, <1 s
├── small state space or graph
│     -> Dijkstra / BFS / DP / A*; exact
├── deterministic, large state space (puzzle/trajectory)
│     -> beam search with state dedup (width 64–2048)
├── cloneable stochastic simulator
│     -> MCTS / rolling-horizon CEM / MPPI
└── unknown black-box dynamics
      -> model-free RL (PPO/DQN), CPU MLP, 4 envs
```

Inspect the environment before training: `inspect.getsource(env.unwrapped.step)`
if available, or probe reset/step transitions. If the task provides a simulator
with known rules, an exact solver is faster and stronger than PPO.

## 3. Best CPU model

1. **PPO with a small MLP** (`[64,64]` or `[128,128]`, tanh), 4 envs, `n_steps=128`,
   `batch_size=128`, `n_epochs=4`, `gamma=0.99`, `gae_lambda=0.95`, `clip_range=0.2`,
   `ent_coef` 0.01 → 0.001. This is the reliable CPU workhorse.
2. **DQN** for discrete actions with a small replay buffer; slower convergence than
   PPO in most competition tasks.
3. **Action masking** for invalid-action environments. `sb3_contrib` **is
   installed** (2.9.2), so `--action-masking --algo ppo` uses `MaskablePPO`
   automatically; if `sb3_contrib` were missing the template falls back to its
   CleanRL masked PPO. Masking is supported for `ppo`/`a2c`/`reinforce`;
   `--algo dqn --action-masking` raises `ValueError`.
4. **Exact/beam/MILP** for deterministic tasks — usually the actual winner.

CPU rules:
- Use `--no-subproc` for env step latency <0.3 ms (gridworld, toy sims): process
  spawn and IPC cost more than the env.
- Use `--subproc` only for heavy physics (>1.5 ms/step), and cap `n_envs` at 4.
- `VecNormalize` observations and rewards; freeze the normalization at eval.
- Potential-based reward shaping (PBRS) if the env gives sparse rewards; it
  preserves the optimal policy.
- Evaluate deterministically every N steps and keep the **best checkpoint**, not
  the last one. PPO often collapses late.

## 4. Feature / observation engineering

- Normalize observations (running mean/std); clip extreme values.
- Frame stacking (4) for partial observability; add time/step features.
- Action mask from `info["action_mask"]` if available; never let the policy choose
  illegal actions.
- Discretize continuous actions only if the task allows it; otherwise use a
  Gaussian policy (SB3 PPO default).
- Reward shaping: distance-to-goal delta, PBRS, penalty for illegal/timeout. Keep
  it policy-invariant where possible.
- Curriculum: start with short horizons/easy seeds, then increase.

---

## 5. Validation

- Evaluate on 10–20 deterministic episodes with fixed seeds; report mean ± std.
- Train 2–3 seeds for the final model; keep the best mean, and ensemble actions by
  majority/mean if the template supports `--ensemble-seeds`.
- Separate train/eval seeds; do not report the best training episode.
- For stochastic environments, average over ≥30 episodes; a single lucky rollout
  is noise.
- Check the submission rollout is reproducible: same seed + same checkpoint →
  same actions.
- If the task scores a single trajectory, verify action bounds and episode length.

## 6. Common pitfalls

| Pitfall | Symptom | Fix |
| :--- | :--- | :--- |
| SubprocVecEnv on a fast env | Slower than 1 env | `--no-subproc` / DummyVecEnv |
| Too many envs | 4 cores thrash | `n_envs=4`, never 8–16 |
| PPO late collapse | Eval reward drops | Best checkpoint, LR decay, entropy schedule |
| Reward scale | Value loss explodes | VecNormalize rewards, clip |
| Illegal actions | Invalid submission | Action masking |
| Eval uses train distribution | Overfit score | Held-out eval seeds |
| Last checkpoint submitted | Worse than mid-training | Save/evaluate every N steps |
| Pixel observations | 1M steps takes days | Do not start; use features/downsample |

# Example: binary assignment minimizing cost with capacity constraints
c = np.array([...])                    # objective
A = np.vstack([...]); b_u = np.array([...]); b_l = np.full_like(b_u, -np.inf)
res = milp(c=c, integrality=np.ones(len(c)), bounds=Bounds(0, 1),
           constraints=LinearConstraint(A, b_l, b_u),

### 7.2 PPO config that survives CPU

```python
from stable_baselines3 import PPO
from stable_baselines3.common.vec_env import DummyVecEnv, VecNormalize

venv = DummyVecEnv([make_env(seed=i) for i in range(4)])
venv = VecNormalize(venv, norm_obs=True, norm_reward=True, clip_obs=10.0)
model = PPO("MlpPolicy", venv, n_steps=128, batch_size=128, n_epochs=4,
            learning_rate=3e-4, gamma=0.99, gae_lambda=0.95, clip_range=0.2,
            ent_coef=0.01, policy_kwargs=dict(net_arch=[128, 128]),
            device="cpu", verbose=1)
model.learn(total_timesteps=100_000)
```

## 9. Do not attempt without GPU

- Pixel/Atari RL, CNN policies, frame stacks of 84×84×4 at 1M+ steps.
- MuJoCo continuous control at 1M steps (SAC/TD3) on CPU.
- Multi-agent RL, world models, Dreamer, offline RL on large datasets.
- Hyperparameter sweeps over 5 seeds × 500k steps.
- GPU-only vectorized simulators or `n_envs` > 8.
