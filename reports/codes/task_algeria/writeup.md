# Task Algeria — «Here, at your service!» (LoRA-адаптер регистра)

## Цель

Обучить LoRA-адаптер для квантованной базовой модели `HuggingFaceTB/SmolLM2-360M-Instruct-GGUF`,
чтобы ответы следовали регистру из `register/RULES.md` (зачин `Sem,`, шесть классов с суффиксами
`-um/-ir/-ak/-eth/-ol/-esh`, печати `ta/man/ras/set/lo/ki`, замена табличных слов на stems,
суффиксы на именах, орфография цифр), при этом отвечая по существу, а вызов «одно существительное»
давал одно существительное с правильной печатью (sealed). Сдаётся `adapter.gguf` (LoRA-адаптер,
не слитая модель).

## Гейты оценки (evaluation_script.py)

| Гейт | Порог | Что измеряет |
|---|---|---|
| `style` | >= 0.15 | средняя доля «чистых» предложений (style_checker) |
| `entity_class` | >= 0.70 | доля сущностей с правильным суффиксом класса |
| `content` | >= 0.55 | доля фактовых промптов, где ответ появляется в de-registered ответе |
| `logprob` | >= -2.6 | средний per-token log-prob de-registered ответа под базовой моделью |
| `calls` | >= 0.75 | 6/8 публичных вызовов = одно чистое предложение + правильная печать |

Ключевое наблюдение: регистр — это **детерминированное поверхностное преобразование** английского
(таблица слов -> stems, имена -> +суффикс, цифры -> названия цифр, печать перед точкой), а факты
базовая модель уже знает. Поэтому LoRA учит именно слой стиля, сохраняя семантику (это же даёт
проход `content` и `logprob`, т.к. de-register возвращает естественный английский).

## Подход

1. **Детерминированный трансформер** `register_transform.py`: plain-English -> register с контролем
   класса имён (`name_class`) и эвристикой для известных классов (города=C, страны/природа=A,
   люди=B, языки=E, цифры=D, товары=F). Каждая выдача проверяется `style_checker` (conformance 1.0).
2. **Корпус** `build_corpus.py` -> `corpus.jsonl` (761 пара): 79 публичных промптов + 8 вызовов +
   синтетическая база знаний (столицы, языки, авторы, первооткрыватели, природа, числа, дни),
   покрывающая все шесть классов и «одно существительное» паттерн.
3. **Обучение LoRA на Kaggle GPU (T4)** (`kaggle/main.py`): PEFT, r=16, alpha=32, все 7 проекций
   (q/k/v/o/gate/up/down), fp16, 3 эпохи. CPU-обучение 360M-модели признано нереалистичным
   (локальный CPU перегружен), поэтому оценка перенесена на GPU через `kaggle_runner.py`.
4. **Конвертация** `solve.py`: PEFT-папка -> `adapter.gguf` через shipped `tools/lora_to_gguf.py`
   (gguf `general.type=adapter`, тензоры `blk.N.*.weight.lora_a/b`).
5. **Оценка** на публичных данных `evaluation_script.py --model adapter.gguf`.

## Файлы

- `register_transform.py` — детерминированное преобразование English -> register.
- `build_corpus.py` — сборка и валидация корпуса.
- `kaggle/main.py` — GPU-обучение LoRA.
- `solve.py` — конвертация + оценка.
- `gen_check.py` — spot-check генерализации на произвольных промптах.
