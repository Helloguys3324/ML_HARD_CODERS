# task_ethiopia — «The Azmari's Borrowed Melody» (Audio Splice Forensics)

**Сложность:** Medium · **Очки:** 200 · **Тип:** file (принимается `main.py`)

## Суть задачи

Дана запись (~56 с, mono 22050 Гц, int16) живой мелодии (azmari — приводной флейте
*washint*/голос). Внутри записи несколько секунд реальной мелодической фразы
заменены другим дублем — «фразой, которую в этой дубле не играли». Склейка сделана
аккуратно: нет клика, щелчка, скачка громкости. Нужно найти **начало и конец замены**
в секундах от начала файла и отдать их парой `start_s,end_s`.

Тренировочная разметка: `data/train-output.csv` → `14.960,20.965` (замена ≈ 6.0 с).

Оценка: 3 скрытых теста, для каждого `|error_start| ≤ 1.5s` **и** `|error_end| ≤ 1.5s`.
Флаг `SIGMOID_<WORD>` выдаётся только при прохождении всех трёх.

## Ключевая идея (что отличает склейку от «слышимого»)

Склейка не слышна на слух (нет клика), но меняет то, что **не зависит от мелодии** —
тембральную/спектральную подпись самой записи:

- микрофон и его позиция, комната/реверберация, дыхание, характер шума, цепочка
  записи — **у дублей всегда немного разные**;
- внутри одного дубля тембр согласован (тот же исполнитель, тот же инструмент, та же
  комната), поэтому каждый нативный фрейм «похож» на весь остальной файл;
- **вставленная фраза — единственный систематический выброс**: её тембр не
  соответствует остальной записи.

Поэтому смотрим не на мелодию/питч, а на **спектральную огибающую (MFCC)** и ищем
фреймы, чей тембр аномально непохож на весь остальной файл.

## Алгоритм (`main.py`, только numpy + scipy)

1. STFT (`n_fft=2048, hop=512`), мел-фильтрбанк (40 полос) → log-mel → DCT → **13 MFCC**.
2. По каждой размерности — центрирование (убираем доминирование громкости/DC), затем
   по каждому фрейму — L2-нормализация ⇒ косинусная мера близости тембров.
3. **Профиль самоподобия**: для каждого фрейма — средняя косинусная близость ко всем
   *остальным* фреймам, исключая окно ±1 с (чтобы протяжная мелодия не «самоматчилась»
   тривиально). Векторизованно O(T·d), без матрицы T×T.
4. Сглаживание (Савицкий–Голей ~0.9 с), робастный порог `median − 1.5·MAD`.
5. Непрерывные «провалы» ниже порога → кандидаты. Выбирается провал с максимальным
   **интегральным дефицитом** (глубина × ширина). Его края = `start_s`, `end_s`.
   Края записи и слишком короткие провалы отбрасываются.

## Результат на тренировке

| | start | end |
|---|---|---|
| truth | 14.960 | 20.965 |
| detected | **14.954** | **20.968** |
| ошибка | 6 мс | 3 мс |

Ошибки на 2–3 порядка меньше допуска 1.5 с. Метод устойчив к вариации всех
гиперпараметров (n_fft 1024–4096, n_mfcc 13/20, mad_factor 1.0–2.0, excl 0.5–2 с,
smooth 0.5–1.5 с): найденные границы во всех вариантах в пределах ±0.3 с от истины.

Видели также: спектральный флюкс/фаза/энергия склейку *не* локализуют (она бесшовная),
а profiling самоподобия — локализует точно, потому что опирается на статистику
записи, а не на транзиенты.

## Проверка обобщения (синтетика)

Взял чистую основу (другой файл — `task_south_african_republic/voice_note.wav`) и
вклеил туда 5-секундный фрагмент флейты с кроссфейдом на границах (симуляция
«аккуратной» склейки). Детектор находил вставку:

- вставка на 20 с → распознано `19.14–24.86` (ошибка 0.86/0.14 с) ✓
- вставка на 40 с → распознано `39.01–44.77` (ошибка 0.99/0.23 с) ✓

т.е. метод не «переобучен» на конкретную позицию трейна.

## Файлы

- `solve.py` — dev-скрипт: прогон + сравнение с разметкой + график.
- `task_ethiopia_analysis.png` — спектрограмма и профиль самоподобия с границами.
