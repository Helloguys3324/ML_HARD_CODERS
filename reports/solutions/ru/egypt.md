# Отчёт о решении: task_egypt («Always Valid, No Excuses»)

## 1. Обзор и цели
- **ID задачи:** `task_egypt` (Египет).
- **Сложность и баллы:** Easy, 100 / 100 баллов.
- **Область:** Парсинг структурированного текста, извлечение шума OCR, детерминированная санация данных.
- **Входные данные:** `test-input.txt` (записи с разделителями строк в кодировке UTF-8). Каждая строка содержит поврежденный вывод оптического распознавания символов (OCR), представляющий запись египтологического архива.
- **Спецификации нормализации данных:**
  1. *Очистка сегментов:* Разделитель — символ вертикальной черты `|`; начальные и конечные пробельные символы должны быть удалены из ключей и значений.
  2. *Подавление артефактов:* Шум сканирования должен отфильтровываться: маркеры страниц (`page 22`), заголовки глав (`Chapter IX`), тире пагинации (`- 45 -`), примечания о дефектах в скобках (`[torn]`, `[illegible]`, `[stain]`), метки иллюстраций (`Fig 3`, `Plate VII`, `footnote 3`) и случайные разделители (`###`, `~~~`).
  3. *Валидация ключей:* Сегмент признается допустимым полем тогда и только тогда, когда он следует синтаксису `key: value` и ключ соответствует регулярному выражению `^[a-zA-Z_][a-zA-Z0-9_]*$`.
  4. *Приведение типов:*
     - Пустые значения $\rightarrow$ JSON `null` (`None` в Python).
     - Точные строки `"true"` / `"false"` $\rightarrow$ логические значения JSON `true` / `false`.
     - Десятичные числа (например, `40`, `0`, `-1264`) $\rightarrow$ нативные целые числа JSON.
     - Все остальные записи $\rightarrow$ JSON-строки (с сохранением экранированных кавычек и слэшей).
     - Разделение выполняется строго по **первому** двоеточию `:` (например, `ratio: 3:1` $\rightarrow$ `"ratio": "3:1"`).
  5. *Инвариант вывода:* Ровно один строго отформатированный JSON-объект на строку, записываемый в `test-output.txt`. Нарушения формата или расхождения в количестве строк приводят к отклонению решения.

## 2. Ключевые выводы и методология

### 2.1 Детерминированный движок правил против LLM-инференса
Хотя в описании задачи предлагалось использовать локальный LLM-оракул (Qwen3-1.7B-GGUF), генеративные языковые модели привносят недетерминированные краевые ошибки: галлюцинированные кавычки вокруг целых чисел, пропущенные разреженные поля, поврежденные escape-последовательности в путях файлов и потенциальные риски таймаута на CPU. Вместо этого был разработан детерминированный движок на основе регулярных выражений с использованием стандартной библиотеки Python, гарантирующий нулевой уровень галлюцинаций и микросекундную пропускную способность.

### 2.2 Фильтрация шума через валидацию идентификаторов
- Разделение строк по символу `|` и фильтрация сегментов, в которых отсутствует `:`, отсекает фрагменты неструктурированного текста.
- Разделение по первому двоеточию (`seg.split(":", 1)`) и проверка условия `^[a-zA-Z_][a-zA-Z0-9_]*$` для `key.strip()` автоматически отсекает сложные шумовые сегменты, содержащие двоеточия (например, `Chapter IX: The Tomb`, `page 22: note`, `[torn]: missing`).

### 2.3 Строгая сериализация в JSON
- Записи сериализуются с помощью `json.dumps(record, ensure_ascii=True, allow_nan=False, separators=(",", ":"))`.
- Использование параметра `ensure_ascii=True` экранирует управляющие символы и переносы строк, предотвращая искажение многострочных записей.
- Корректность десериализации через `json.loads` проверяется в оперативной памяти перед записью файла на диск.

## 3. Детали реализации

1. **`main.py` (Основной парсер):**
   - **`parse_record(line: str) -> dict`**:
     - Удаляет символы перевода строки и разбивает строку по `|`.
     - Проверяет структуру ключа по регулярному выражению `^[a-zA-Z_][a-zA-Z0-9_]*$`.
     - Парсит целые числа по шаблону `^-?(?:0|[1-9]\d*)$`, сопоставляет логические значения и null, а остальные данные преобразует в строки.
   - **`find_input_file(cwd, script_dir) -> Path`**:
     - Находит пути через аргументы CLI, стандартные файлы в рабочей директории (`test-input.txt`, `input.txt`) и сигнатуры содержимого (`|` и `:`).
   - **`main()`**:
     - Обрабатывает входные записи построчно и направляет проверенные JSON-объекты в `test-output.txt`.
2. **`validate.py` (Регрессионный тестовый набор):**
   - Проверяет тестовые данные на `train-output.txt` (13/13 точных структурных совпадений JSON, корректный парсинг путей Windows `C:\papyri\thoth`, внутренних кавычек `"lord of the moon"` и отрицательных чисел).
   - Проверяет краевой случай из спецификации:
     `page 22| king :Menes| title: ruled with "the Aten" |[torn]| alive :true | Chapter IX`
     $\implies$ `{"king":"Menes","title":"ruled with \"the Aten\"","alive":true}`.
   - Подтверждает полное отсутствие отклонений от схемы на пустых строках, встроенных двоеточиях и числовых границах (`ALL OK`).
3. **`main.py.txt` (Резервный файл для платформы):**
   - Побайтово идентичная копия (MD5 `c6693a0ce13bfd3abd6304fa431495b8`), созданная для загрузчиков платформы, принимающих расширение `.txt`.
