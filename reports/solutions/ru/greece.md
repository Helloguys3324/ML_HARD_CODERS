## 1. Что требуется в задаче

Три классификатора-«оракула» на PyTorch — **Ares**, **Athena**, **Apollo** — должны быть
оценены на `test_dataset.csv` относительно `test_labels.csv` при фиксированном пороге
решения **0.50**. Все три имеют **одинаковую точность (accuracy) на тесте**, поэтому победитель
должен быть выбран по метрике, соответствующей заявленному профилю затрат на внедрение:

> «missing a true catastrophic threat is far more expensive than raising a false
> alarm.» («пропуск реальной катастрофической угрозы обходится гораздо дороже, чем ложная тревога.»)

Это условие, чувствительное к затратам, с **C_FN ≫ C_FP**, то есть требует максимизации
**полноты / чувствительности (recall / sensitivity)** (эквивалентно минимизации ложноотрицательных результатов, false negatives; также отражается в F-бета при β>1, сбалансированной точности, MCC, ROC-AUC и PR-AUC). Флаг представляет собой
`SIGMOID_<UPPERCASE MODEL NAME>` для выбранной модели.

## 4. Почему ARES — бизнес-правило принятия решений

Множества предсказаний строго **вложены** (`apollo ⊂ athena ⊂ ares`), что представляет собой
классическую кривую компромисса precision/recall при фиксированной точности:

```
(ares, athena, apollo) -> количество (neg, pos)
(0,0,0) -> 855 neg,   5 pos     # пропущены всеми тремя
(1,0,0) ->  20 neg,  20 pos     # обнаруживает только Ares
(1,1,0) ->  20 neg,  20 pos     # обнаруживают Ares+Athena
(1,1,1) ->   5 neg,  55 pos     # обнаруживают все три
```

Модель затрат: `cost = FP + k·FN`, где `k = C_FN / C_FP`:

| k | ARES | ATHENA | APOLLO | победитель |
|---:|---:|---:|---:|---|
| 0.5 | 47.5 | 37.5 | 27.5 | APOLLO |
| **1.0** | 50.0 | 50.0 | 50.0 | ничья (= одинаковая accuracy) |
| 2.0 | **55.0** | 75.0 | 95.0 | **ARES** |
| 5.0 | **70.0** | 150.0 | 230.0 | **ARES** |
| 10.0 | **95.0** | 275.0 | 455.0 | **ARES** |

Для **любого** `k > 1` (в любых условиях, где пропуск катастрофической угрозы стоит дороже,
чем ложная тревога — а в условии сказано «far more expensive»), **ARES является
оптимальным оракулом**. При `k = 1` все трое показывают равный результат, именно поэтому их accuracy
идентична. Единственное преимущество APOLLO — высокая precision (мало ложных тревог), которую
бизнес-контекст явным образом определяет как менее критичную и более дешёвую ошибку.

Проверка согласованности: ARES также побеждает по **каждой другой метрике, ориентированной на полноту (recall)** —
recall, F1, F2, сбалансированная точность, MCC, ROC-AUC, PR-AUC — поэтому вывод не зависит
от выбора конкретной метрики. Athena превосходит Apollo по всем этим показателям; только
precision и specificity ранжируют их в обратном порядке.
