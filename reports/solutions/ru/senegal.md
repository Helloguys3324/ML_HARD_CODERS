# Отчёт о решении: task_senegal ("The Teranga FM Token Diet")

## 1. Обзор и цели задачи
- **Task ID:** `task_senegal` (Сенегал).
- **Сложность и баллы:** Medium, 200 / 200 баллов.
- **Область:** General AI / Оптимизация затрат LLM и динамическая маршрутизация запросов.
- **Формат вывода:** Таблица маршрутизации `routing_config.json` и флаг `SIGMOID_<NAME>`.
- **Постановка задачи:**
  - Общественная радиостанция Teranga FM в Каолаке (арахисовый бассейн Сенегала) запустила SMS-линию помощи фермерам на базе API инференса LLM.
  - Базовое решение направляло все входящие запросы в модель старшего уровня (high-tier) с многословным стилем (verbose), примерами (few-shot) и полным контекстом без обрезки, расходуя 2,277 токенов на тестовый пакет.
  - Цель — построить оптимальную таблицу маршрутизации (`routing_config.json`) для 20 эталонных вопросов из `fact_bank.json`, сохранив 100% точность ответов (20/20 `PASS`) в рамках жёсткого лимита не более **1,200 токенов суммарно** (сокращение на ~49%).

---

## 2. Ключевые идеи и механика маршрутизации
- **Логика симулятора и верификации (`model_utils.py`):**
  - **Критерий успешности (`question_passes`):** Ответ удовлетворяет вопросу тогда и только тогда, когда в каждом обязательном фактологическом слоте содержится хотя бы одна допустимая ключевая фраза из `slot["phrasings"]` в виде подстроки.
  - **Условие включения слота (`render_completion_body`):**
    $$\text{assisted} \lor \neg \text{slot}[\text{"large\_only"}], \quad \text{где } \text{assisted} = (\text{tier} == \text{"large"}) \lor \text{context}$$
  - **Влияние параметров на стоимость:**
    - `fewshot`: Создаёт существенный оверхед в промпте, не влияя на доступность слотов $\implies$ `fewshot = False` для всех вызовов.
    - `style`: `verbose` добавляет шаблонные вводные и заключительные фразы; `terse` формирует компактный фактологический текст $\implies$ строго `style = "terse"`.
    - `context`: Контекстные фрагменты RAG требуются только для уровня `cheap` при обработке слотов `large_only`. Для уровня `large` передача контекста избыточна.
- **Оптимальная стратегия маршрутизации:**
  - **Вопросы без слотов `large_only` (8 запросов):** Назначаются на уровень `cheap` без контекста (`cheap / terse / fewshot=False / context=False`).
  - **Вопросы со слотами `large_only` (12 запросов):** Оценка затрат: выбирается конфигурация `cheap + context=True`, если стоимость токенов контекста ниже разницы в цене перехода на `large + context=False`.

## 3. Детали реализации
Пайплайн оптимизации управляется через `solve.py` и валидируется в `main.py`:

1. **Скрининг сетки параметров (`solve.py`):**
   - Для всех 20 вопросов вычисляет все 16 комбинаций прямого произведения:
     $$\text{tier} \in \{\text{"cheap"}, \text{"large"}\}, \; \text{style} \in \{\text{"terse"}, \text{"verbose"}\}, \; \text{fewshot} \in \{\text{False}, \text{True}\}, \; \text{context} \in \{\text{False}, \text{True}\}$$
   - Симулирует вывод через `mu.build_call(...)` и проверяет `mu.question_passes(...)`.
2. **Минимизация затрат с ограничениями:**
   - Отсекает невалидные комбинации и выбирает конфигурацию с минимальным расходом токенов для каждого запроса:
     $$c^*(q) = \arg\min_{c \in \mathcal{C}_{\text{pass}}(q)} \text{Tokens}(q, c)$$
   - *Группа A (8 запросов: `q01`, `q03`, `q09`, `q11`, `q14`, `q15`, `q16`, `q19`):* Направлены на `cheap / terse / fewshot=False / context=False`.
   - *Группа B (12 запросов со слотами `large_only`):* Динамически переключаются между `cheap + context` и `large` в зависимости от длины контекстного сниппета.
3. **Исполнение и упаковка (`main.py`):**
   - Экспортирует выбранную конфигурацию в `routing_config.json`.
   - Запускает пакетную обработку `fact_bank.json`, сохраняя проверенные ответы в `answers.json` и формируя `submission.json`.
